# builder `@Middleware` Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** `@Middleware(log, hystrix, …)` on an `@Provide` constructor makes builder generate a decorator of the provided interface that runs the plugins around every method, wired so every consumer in the app receives it.

**Architecture:** `NewSpec` parses `@Middleware`, loads the interface with go/types through an injected `PackageLoader`, validates it and attaches each middleware to the apps whose doors reach the constructor in the inject graph. `Render` writes one decorator package per constructor under `builder/middleware/<import path>/` exposing `Decorate<Func>() fx.Option` (a root `fx.Decorate`), and each app's `Modules()` lists the decorators it reaches.

**Tech Stack:** Go 1.26, go.uber.org/fx v1.24.0, golang.org/x/tools/go/packages, go/types, `extra/middleware`, `factory/local/extra/middleware`.

**Spec:** `docs/superpowers/specs/2026-10-18-builder-middleware-design.md`

## Global Constraints

- Header `// Code generated by builder; DO NOT EDIT.` on every generated file.
- Plugin names → packages (fixed import aliases):
  - `log` → `logmw` `github.com/xgodev/boost/factory/local/extra/middleware/plugins/local/wrapper/log` (exists already)
  - `hystrix` → `hystrixmw` `…/plugins/contrib/afex/hystrix-go/v0`
  - `datadog` → `datadogmw` `…/plugins/contrib/datadog/dd-trace-go/v1`
  - `prometheus` → `prometheusmw` `…/plugins/contrib/prometheus/client_golang/v1`
- Wrapper name = `strings.ToLower(<package name> + "." + <interface> + "." + <method>)`.
- Wrappers are built with `fmiddleware.New{AnyError,Any,Error}WrapperWithOptions(ctx, &fmiddleware.Options{Name: name}, plugin funcs…)` (`factory/local/extra/middleware`), which drops disabled (nil) plugins.
- `returnFunc` is the identity; `exec` calls `next` with the exec's ctx.
- Commits in English, no `Closes #N`, push after each commit, comment on #72 per push.

## Review Focus

1. Interface method using an unexported type → generation fails with NotValid (decorator could not name it).
2. Variadic method → decorator signature uses `...T` and calls `next.M(ctx, aN...)`.
3. Interface embedding another interface (other package) → every embedded method is decorated.
4. Method named `Next`/`next` → no field clash with the `next` field (fields are `<method>Wrapper`).
5. `@Provide(name=x)` → decorator annotated with `ParamTags(``, name:"x")` / `ResultTags(name:"x")`.

# inject: implementation switch by config (`@Default`) -- design

Issue #75. Piece 2 of the builder boilerplate roadmap
(`docs/builder-boilerplate/README.md`), after `@Middleware` (#72).

## Intent

A contract with two or more implementations (`quote.Service` served by
`local` and by `resty`) needs a hand-written fx module today: `sync.Once`,
`module(impl)`, a `switch` on a config key, the existing implementation as
default and a boot failure on an unknown value (claude-plugin Go LAW 23).
inject even refuses the two `@Provide` (AlreadyExists). The maintainer wants
that module generated: the implementations carry annotations, config picks
one at boot.

## Decided (by the maintainer)

```go
// package local
// @Provide(index=0)
// @Default
func New() quote.Service { ... }

// package resty
// @Provide(index=0)
func New(c *resty.Client) quote.Service { ... }
```

- Each implementation keeps only its `@Provide`; the implementation **name is
  its package name** (`local`, `resty`), not written in the annotation.
- One implementation carries `@Default`: it is wired when the key is unset.
- The generator writes the switch; config chooses the implementation by
  name, under `<interface package>.implementation`.
- The claude-plugin Go skill is updated with it (LAW 23 stops asking for the
  hand-written switch).

## Behaviour

- Two or more `@Provide` of the same value (same type and `name`, no `group`)
  with exactly one `@Default` among them form an **implementation set**.
- Config key: the package path of the provided type, relative to the Go
  module, in dots, plus `.implementation`
  (`internal/pkg/domain/service/quote` ->
  `internal.pkg.domain.service.quote.implementation`, env
  `INTERNAL_PKG_DOMAIN_SERVICE_QUOTE_IMPLEMENTATION`). A named value adds its
  name: `<package>.<name>.implementation`. A type outside the module uses
  its full import path. Default value: the `@Default` package name. The key
  is registered with `config.Add` in the generated file's `init()`.
- The switch module includes **only** the chosen implementation's module, so
  the others and their dependencies (an HTTP client, a database) are never
  built.
- An unknown value fails the boot with `fx.Error(NotValid)` naming the key,
  the value and the valid names; it never falls back to the default.
- Every consumer of the value, and the root `gen.Module()`, includes the
  switch module instead of the implementations' modules. The graph still links each consumer to every
  implementation (cycles and builder reachability see all of them).
- `@Middleware` on an implementation of a set runs only when that
  implementation is wired: its `Decorate<Func>()` returns an empty option
  otherwise.

## Validation (generation fails, nothing written)

- two providers of the same non-group value and no `@Default`
  (AlreadyExists, the message suggests `@Default`);
- two `@Default` in one set;
- `@Default` on a function without exactly one `@Provide`, on a group
  provide, with `@Invoke`, or on a value with no other implementation;
- two implementations of a set in packages with the same name;
- two sets with the same config key (AlreadyExists);
- a set used where builder needs a single constructor: the receiver of a
  `@REST`/`@Function` method, or a `@GRPC` constructor.

## Non-goals

- Switching a group, or switching by anything other than config.
- Switching at runtime after boot.
- Generating the implementations' own knobs (`config.go`): piece 3.

## Anti-goals

- A hand-written switch module left in the example or the skill.
- Building an implementation that was not chosen.
- Falling back silently when the key holds an unknown name.

## Left to the builder

- My call: `@Default` lives in `inject` (it changes the graph and the
  generated modules), builder only consumes it (reachability, `@Middleware`,
  door validation).
- My call: the switch file is
  `gen/<type import path>/<lower type>_implementation.go`, exposing
  `<Type>ImplementationModule()` with the same `sync.Once` guard as the other
  generated modules, and an exported accessor of the key the
  `@Middleware` decorator reads. Generated header: `// Code generated by
  inject; DO NOT EDIT.`
- My call: the name `@Default` keeps the maintainer's choice even though the
  inject README already says "default provider" for a provider without
  `name`; the docs call it the "default implementation" to keep the two
  apart.
- My call: in the example, the in-memory store moves to `stock/memory`
  (`@Default`, keeps `@Middleware(log, prometheus)`) and a second
  implementation `stock/unlimited` (every item available) is added, so the
  key is `builder.examples.simple.stock.implementation`.
- Test shape: goldens for the switch file, table tests per validation error,
  and the example (`builder/examples/simple`) gets a second implementation of
  `stock.Service` with an e2e test per key value (default, the other, an
  unknown value failing the boot).

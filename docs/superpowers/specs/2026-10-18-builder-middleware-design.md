# builder `@Middleware` — design

Issue #72. First piece of the builder boilerplate roadmap
(`docs/builder-boilerplate/README.md`).

## Intent

`extra/middleware` runs a chain (log, hystrix, datadog, prometheus) around a
call, but today every service builds its wrapper by hand and wraps every
method body in `wrapper.Exec(ctx, id, func…)`. The maintainer wants the code
clean: the service implements its interface with plain methods, and one
annotation on its constructor says which middlewares run around every method.
builder generates the rest.

## Decided (by the maintainer)

- The middleware list lives **in the annotation**; config only **turns each
  one off**.
- The annotation goes with the builder annotations and is generated by the
  same `go generate` run.
- The claude-plugin Go skill is updated with it (separate repo,
  `xgodev/claude-plugin`).

## Syntax

```go
// New provides the quote client.
// @Provide(index=0)
// @Middleware(log, hystrix, datadog, prometheus)
func New(c *resty.Client) quote.Service { ... }
```

- Positional plugin names, at least one, no duplicates. The first is the
  outermost (runs first, returns last).
- Goes on a function with exactly one `@Provide`; the provided result
  (`index`) is a named, non-generic interface type. `name` on that `@Provide`
  is allowed: the decorated value keeps it. `group` is rejected: a decorator
  of a group receives the whole group.
- The annotation parser accepted only `key=value` values; it now also accepts
  bare names (`annotation`), kept in `Value` and left out of `Map`.

## Behaviour

- builder loads the interface's method set (embedded interfaces included) and
  generates a decorator type implementing it. Every consumer of the interface
  in the app receives the decorator, whatever module it lives in; an app that
  never uses the constructor gets neither the decorator nor its plugin imports.
- Per method, by its results:
  - `error` → `middleware.ErrorWrapper`
  - `(R, error)` → `middleware.AnyErrorWrapper[R]`
  - `R` (one non-error result) → `middleware.AnyWrapper[R]`
- Each method calls `wrapper.Exec(ctx, name, exec, returnFunc)`, where `exec`
  calls the real implementation with the same arguments (variadic passed with
  `...`) and `returnFunc` returns the result and error unchanged (hystrix calls
  it on its fallback path; nil would panic).
- Wrapper `name` = `<package name>.<interface>.<method>`, lowercased
  (`quote.service.quote`). It is the hystrix command, the span/metric name and
  the config path of each plugin:
  `boost.factory.local.extra.middleware.plugins.<plugin>.<name>.enabled`.
- Plugins come from `factory/local/extra/middleware/plugins/...`
  (`NewAnyError[R](ctx, name)`, `NewAny[R]`, `NewError`): a plugin that returns
  nil (disabled by config) is left out of the chain.

| Annotation name | Package |
|---|---|
| `log` | `factory/local/extra/middleware/plugins/local/wrapper/log` (exists, `enabled` default `true`) |
| `hystrix` | `factory/local/extra/middleware/plugins/contrib/afex/hystrix-go/v0` |
| `datadog` | `factory/local/extra/middleware/plugins/contrib/datadog/dd-trace-go/v1` |
| `prometheus` | `factory/local/extra/middleware/plugins/contrib/prometheus/client_golang/v1` |

## Validation (generation fails, nothing written)

- unknown or duplicated plugin name, empty list;
- function without exactly one `@Provide`, or the provided result is not a
  named non-generic interface;
- a method without `context.Context` as first parameter, with no result, or
  with results other than `error`, `(R, error)` or `R`;
- two decorated methods with the same `name`;
- an app named `middleware` (`gen/builder/middleware` holds the decorators).

## Non-goals

- `cache` and `fallback` middlewares (they need a cache manager or a fallback
  function per method); a later piece.
- Different middlewares per method: the list applies to every method.
- Decorating concrete types: the Go skill's services already return
  interfaces (LAW 22).

## Anti-goals

- Domain code importing boost or a vendor SDK: the annotation is a comment,
  the decorator lives in `gen/`.
- Hand-written `wrapper.Exec` left anywhere in the example or the docs.

## Left to the builder

- My call: plugins are built once, when the decorator is built, with the
  `context.Context` of `fx/modules/core/context`; the `name` scheme above.
- How the decorator reaches every consumer: a root `fx.Decorate` in
  `gen/builder/middleware/<import path>/<func>_middleware.go`, exposed as
  `Decorate<Func>()` and listed in `Modules()` of each app that reaches the
  constructor. The interface comes from go/types through a `PackageLoader`
  passed to `NewSpec`.
- Test shape: goldens for the decorator, table tests for each validation
  error, and the example (`builder/examples/simple`) gets an interface whose
  constructor carries `@Middleware`, with an e2e test proving the consumer
  receives the decorator.
- `builder/README.md` gains the `@Middleware` section.
